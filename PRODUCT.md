# Product

<!-- impeccable:product-schema 1 -->

## Platform

web (installable as a PWA), plus a signed JSON API for the mobile app

## Users

Any developer with a GitHub account. They come to post short updates, follow other developers, read logs of what those people are saying, and talk to them privately. Every account is a GitHub account; there is no other way in. Guests and crawlers can read public content without signing in.

## Product Purpose

/dev/null is a social network for developers: sign in with GitHub, get a profile mirrored from GitHub, follow people, commit short text (with code, images, links, or a poll), and read the logs. Success is developers choosing to post and read here because the people on it are verifiably developers.

## Positioning

Identity is GitHub. Every account is a real GitHub user, and the profile (avatar, name, username, bio, company, location, website) is mirrored from GitHub on every login, or on demand with "Sync from GitHub" in settings, and cannot be edited on /dev/null. A general-purpose network cannot truthfully claim that every account is a developer with a public GitHub identity.

## Operating Context

- Sign-in is GitHub OAuth only. New GitHub accounts are screened once, at signup: by default at least 7 days old with a verified primary email (`SIGNUP_MIN_ACCOUNT_AGE_DAYS`, `SIGNUP_REQUIRE_VERIFIED_EMAIL`). Profile changes happen on GitHub ("Edit on GitHub"), then sync at next login or with "Sync from GitHub" (once a minute). Locally, `/login` asks for any username instead of GitHub.
- Guests can read: the Latest and Trending logs (guests land on Trending at `/`), profiles and their follower and following lists, approved commits with their threads, photos, search, and the about, brand, changelog, terms and privacy pages. Signing in is needed to write, follow, star, save, vote, report, give pastéis, translate, or reach the Following log, Notifications, Saved, Remotes and Settings. A guest who clicks one of those actions goes straight to GitHub and comes back to the profile or commit they were reading; a guest who types a signed-in-only URL lands on `/`. Pending, rejected and deleted commits are a 404 for guests.
- Link previews: profiles, approved commits, and the static pages unfurl for guests and crawlers with Open Graph and JSON-LD metadata. A commit uses its attached images, otherwise a drawn `og.png` with the author, body and reply count; a profile's `og.png` shows the bio and counts. Sitemaps list users with approved commits and every approved commit.
- Public read API: read-only JSON under `/api/v1`, no authentication, for public profiles (with counts), a user's commits or replies, and single commits. It returns exactly what a guest's link preview may show: approved, non-deleted commits only (with their images), approved reply counts, and a parent only while it is approved. Never emails or other hidden profile fields. 60 requests a minute per IP.
- Signed API: the mobile app uses the same `/api/v1`, signing every request with an SSH key it keeps on the device, which the user approved as a device (no passwords or API tokens). The app signs in like an OAuth app with PKCE: it opens `/mobile/authorize` in a browser, the user signs in with GitHub if they need to and approves it, and the app redeems the one-time code (valid 5 minutes) for the device with a request signed by that key. The approval is the proof, so the key doesn't need to be on GitHub, and a key that is on GitHub, like one made for the GitHub Action, can't use the API without it. Devices are listed, with when each was last used, and revoked under Settings → Devices. A signed request to a public endpoint gets what the web shows that user, such as their own pending commits. Signed-only endpoints read the signed-in user, the logs, replies, notifications, saved commits, mutes and blocks, and commit, reply, quote, delete, follow, star, save, mute, block, switch pastéis mode and give pastéis, report commits, sync from GitHub, save the lane color, and delete the account, with the web's validation, moderation, and rate limits. Signed bodies are JSON, so the API takes text commits, replies, and quotes only: no images, polls, or link-card choice. A bad or expired signature is a 401, never the public view. 120 requests a minute per user.
- Terminal commits: `curl -fsSL https://dev-null.sh/commit | bash -s -- 'Hello world!'` signs a commit locally with an Ed25519 or RSA key whose public half is on the user's GitHub account (authentication or signing key), and /dev/null verifies the signature. `--reply` replies to a commit by hash or link, `--image` attaches up to 3 images (no descriptions). Settings → Terminal shows it, and a GitHub Action (`nunomaduro/dev-null.sh/.github/actions/commit@production`) does the same from a workflow with a key kept in the repository's secrets. Terminal commits always take the first link as their card and need 3+ characters even with images.
- Profile feeds: every profile has an Atom feed of its latest 50 approved top-level commits at `/@{username}/feed.atom`, their images as enclosures, advertised with `<link rel="alternate">` on the profile's guest preview.
- Each profile's commit activity graph is also public as an SVG at `/@{username}/graph.svg` (`?theme=light|dark|auto`, light by default), for embedding in GitHub profile READMEs. It draws the last year of approved commits with the streaks, in the user's lane, and is cached for an hour.
- First sign-in leads to a short setup at `/onboarding`: confirm the mirrored profile, pick a color, follow a few of 5 suggested developers, learn the composer, `?` shortcuts and terminal commits, then land on the log (or the page the user was headed to). Skippable at any step (Skip setup or Esc); finishing or skipping ends it for good. Accounts that existed before it never see it.
- New accounts start as mutual followers of **@tom** (no notification), and their GitHub follows come over once: you follow the developers you follow on GitHub, and the ones following you there follow you (up to 1,000 each way, skipping blocks), with follow notifications only for a brand-new account. It only ever adds follows, so unfollowing someone sticks. `php artisan follows:import` does the same, silently, for everyone not imported yet.
- Three logs, 20 commits a page with infinite scroll, top-level commits only (quotes included), muted and blocked authors left out, your own pending commits shown to you: **Following** (my commits plus people I follow; signed in only), **Latest** (everyone, newest first), and **Trending** (everyone, ranked by a hot score: distinct other developers engaging with the thread, a reply or quote worth three stars, against age, so engagement must double to keep up with a commit 6 hours newer; pastéis don't count). `/log/everyone` redirects to Trending. The last log shown is remembered for `g l` and after sign-in. Following and Latest poll every 30 seconds for an "N new commits" pill and mark where you left off; touch swipes move between logs. An empty Following log suggests 3 recent commits from people to follow. **Who to follow** suggests 3 people in the right column (inside the log below xl), with a reason, refresh, and "Don't show again".
- Profiles live at `/@{username}` with commit, following, and follower counts, a "Follows you" badge, the level and Unix rank (opens the achievements), an activity graph with longest and current streaks (24 hours, 7 days, 30 days or a year, depending on how old the first commit is), a "Sponsor on GitHub" link when the user has a Sponsors listing, Share, and Commits and Replies tabs. Commits is the default, with the pinned commit on top; `?tab=replies` lists their authored replies with visible parent context. Across a block in either direction a profile is unavailable.
- Settings has five tabs. **Profile**: the read-only GitHub profile with Edit on GitHub and Sync from GitHub, color (Auto, one of the six graph lanes, or a custom hex color; the only identity setting /dev/null owns), timezone (shared so others see your local time, or unset to use the browser's), Pastéis mode, Remotes on or off, the Markdown snippet and live preview to embed the activity graph SVG, Download JSON export, delete account. **Appearance** (kept in browser cookies, so per browser): theme (light/dark/system), navigation expanded or collapsed, lane dimming (on by default: other commits fade while the pointer rests on one), replies shown per commit (1, 3, 5, 10, 15, 20 or 25; 3 by default), and Who to follow shown or hidden. **Terminal**: the script and the GitHub Action. **Safety**: muted and blocked people, each undoable. **Devices**: the mobile app on each device the user approved, when it was last used, and revoking it.
- Moderators are the site admins: GitHub usernames listed in `ADMINS`. They review the moderation queue (`/moderation`: pending commits oldest first with the automated verdict and a translation, approve or reject with an optional reason up to 280 characters, bulk approve up to 100, `a`/`x` shortcuts) and the reports queue (`/moderation/reports`).
- Operations (`/operations`, admins only; a 404 for everyone else), in tabs like Settings. Health: database and cache connectivity, the GitHub API rate limit when GitHub credentials are configured, the database queue backlog per queue with the age of its oldest job, the most recent failed jobs (each can be retried or forgotten), pending moderation and link previews, and link previews that came back without metadata in the last 24 hours. Features: site-wide feature switches (today only translations). Activity: today's signups, commits, replies, and active authors next to yesterday's, the same four counts since the first signup, an activity graph of everyone's commits, replies, or signups over the last 24 hours, 7 days, 30 days, or year, and the same window's commits and replies by moderation status and by their ten busiest authors. Traffic, when a Fathom token is configured: visitors over a chosen range. Every tab refreshes every 15 seconds.
- Installable as a PWA with shortcuts to Following, Latest and Notifications. The service worker caches only the release's built assets and shows an offline page; pages are never cached, and there are no push notifications.
- The changelog is a dialog fed by the pull requests merged into `production` on GitHub. `/brand` offers the logo, wordmark, colors and wallpapers (also from a right-click on the nav logo).

## Capabilities and Constraints

- Commits (posts): text with code, 3–4,000 characters, or up to 3 images with optional text; create and delete only (no editing). Feeds fold a commit after 280 characters or 8 lines behind "Show more". Commits, replies, quotes, scheduled commits, terminal and API commits share one budget of 10 a minute per user.
- Moderation: a commit is approved at once when its author is an admin, or has a good reputation (account older than an hour, at least one approved commit, at least 10 followers) and no undismissed report on their commits in the last 7 days. Everyone else's commits are pending until approved: OpenAI moderation (when configured) approves clean ones, rejects only near-certain violations, and leaves the rest for a moderator. Pending and rejected commits are visible to their author only; images of a pending commit to its author and admins. A rejection notifies the author with the reason, never the moderator; approval notifies nobody.
- Images: JPEG, PNG or WebP, up to 10 MB and 6,000 px a side, with a description up to 1,000 characters, by picker, paste or drop. Every image is re-encoded to WebP at most 1,600 px wide, which strips its metadata. A photo viewer opens them at `/@{username}/commits/{id}/photos/{n}`, with download and the description. Images and a poll can't share a commit.
- Polls: on top-level commits, 2–4 distinct options up to 50 characters, open for 1 hour, 1 day, 3 days or 7 days from approval. One vote per person, final; the author can't vote. Results show to the author and voters, and to everyone once closed; who voted for what is never shown.
- Scheduled commits: a top-level commit (images or poll included, not a reply or quote) can be scheduled up to 30 days ahead, 10 outstanding at most, from the composer. It stays private until the scheduler submits it (every minute), then goes through the usual moderation. `/scheduled-commits` lists queued and submitted ones; queued ones can be canceled.
- Follow/unfollow, idempotent; self-follow and follows across a block are rejected.
- World: the account @world replies "Hello, {name}." when an approved commit or reply's whole text is hello world, including "Hello, World!". A pending one is answered once it is approved, and only once. @world does not sign in.
- Tom: **@tom** is a friendly bot, inspired by MySpace Tom. Mention him in a public commit or reply and, once it is approved, he answers under it once (an AI model through OpenCode, when configured), about /dev/null's features, story and stack from `KNOWLEDGE_BASE.md`, or with public commits on a topic. He reads at most the 12 public commits above it, never sees anything private, and has remotes off. He is not a general assistant.
- Achievements: profiles show 13 badges (init, syntax, uptime, daemon, sysadmin, stdout, kernel space, stargazer, superstar, pipe, authorized_keys, sweet tooth, luddite) and an XP level with a Unix rank (user, daemon, operator, maintainer, wheel, root), computed from current activity rather than stored, so they can be lost again.
- Replies: any visible commit can be replied to; a reply is itself a commit (same limits, images, moderation, and rate limit; no poll, quote, or schedule). Threads expand inline under a commit, a few replies at a time as set in Appearance; logs and the profile's Commits tab list top-level commits only, while the profile's Replies tab lists that user's replies. Quotes of a commit are listed among its replies and counted with them. Every commit has its own page with its ancestors above it and its replies expanded. When its author replied to it themselves, their earliest such reply continues it, and so on: the page reads that thread in order under the commit, 10 commits at a time with "Show more of this thread", each marked with its place (`3/7`, with a `+` when more than 100 commits follow). The next commit of the thread is left out of the replies and their count, and the commit's other replies stay folded until asked for. It stops at the first reply the viewer can't see, or where the author has no further reply to themselves (deleted ones don't count), and none of it shows if the viewer muted the author. Elsewhere (logs, profiles, Saved, search, and nested replies), a commit its author continued this way shows "Show thread", which opens its page. Deleting a commit removes it from logs, profiles, counts, and its own page, but never takes other people's replies with it: while it still has visible replies or quotes it stays in its thread as a `[deleted]` tombstone with no author or body, and it can no longer be replied to. Its author can undo a deletion for 30 seconds, which brings it back with its images and pin, without notifying anyone again; the notifications it had are gone for good. A commit that is deleted or hidden while someone is reading it stays on their screen with its actions off. Deleting an account erases that user's commits and replies for good, along with every reply under their commits; replies other people left under their replies survive, under the same authorless `[deleted]` tombstone.
- Quotes: any visible commit can be quoted. A quote is a new top-level commit (same limits, images, moderation, and rate limit; no preview, link-card choice, poll or schedule) with the quoted commit embedded under its body as a compact card that opens the quoted commit's page; a reply cannot also quote. The embed only ever shows what the viewer can see: a deleted quoted commit leaves a `[deleted]` tombstone, one the viewer can no longer see (pending or rejected) reads `[unavailable]` with no author or body, and erasing an account removes embeds of erased commits, while approved quoted replies retained as authorless thread tombstones still read `[deleted]`. A quote also appears among the quoted commit's replies and counts in its reply count.
- Stars: anyone who can see someone else's commit can star and unstar it; your own can't be starred. Starring is idempotent. The count sits on the commit and stays live while it is on screen. A star notifies the author, and unstarring removes that notification. A star is the engagement action, named the way GitHub names it, and it is not a git ref.
- Saved: any visible commit or reply can be saved, privately, without telling its author, and read back at `/saved`, newest saved first.
- Pins: one of your own top-level commits can be pinned to the top of your profile's Commits tab; a new pin replaces the old one.
- Pastéis: with Pastéis mode on (Settings → Profile, off by default), you can give pastéis (a pastel de nata icon, a tribute to the pastéis de nata brought to the livestream) to other people's commits, several per commit, 10 a day, resetting at 00:00 UTC. They notify nobody and don't rank anything. With the mode off, their controls and counters are hidden but you still receive them.
- Mentions: `@username` in a commit or reply mentions that developer and links to their profile (through their id, so it survives renames); unknown usernames stay plain text. Typing `@` in either composer suggests up to 6 developers (people you follow on a bare `@`, then matches by name or username, people you follow first, never muted or blocked people); ↑↓ to move, ↵ or Tab to pick, Esc to dismiss. Any number of people can be mentioned in one commit. Emails, scoped packages (`@inertiajs/react`), domains (`@vue.js`) and mentions in code are not mentions.
- Reports: anyone who can see an approved commit or reply that isn't theirs can report it privately, with a reason (spam, harassment, unsafe, other) and optional details (up to 500 characters). One report per commit per person, 5 reports a minute; reporting never changes the commit's visibility, but an undismissed report keeps its author's new commits pending for 7 days. Moderators review open reports oldest first without the reporter's identity, and either dismiss a report to keep the commit or reject the commit, which clears its reports from the queue. Deleting a commit keeps its reports, so it can't lift that hold.
- Composer: the main composer, reply, and quote. Both the main and reply composers toggle between writing and a preview of the draft rendered exactly as the posted commit (code highlighting, inline code, emoji, mentions, links, attached images, poll), with the URL that will get the link card marked. The eye button or ⌘/Ctrl+Shift+P toggles it; Esc in the preview goes back to writing. Every composer checks drafts for secrets on the device and asks before publishing one ("Remove detected secrets" redacts them). Unfinished drafts (text, images and their descriptions, not polls or schedules) are stashed in the browser per user and per reply or quote, never synced, and cleared on sign-out.
- Bug reports and feature requests: a main-composer draft that starts with `/bug ` or `/feature ` becomes an issue draft and opens a public GitHub issue on `nunomaduro/dev-null.sh`, credited to the user, instead of a commit. Text only, 3–4,000 characters, no detected secrets, 5 opened issues an hour.
- Translations: commits and replies in another language than the reader's browser offer Translate (signed in, 10 a minute), done by an AI model through OpenCode and cached for 7 days. The original never changes; "Show original" switches back. Admins can translate pending commits in the moderation queue and can switch translations off for everyone in Operations → Features. Remote messages are never translated.
- Link cards: a commit or reply with links shows a card (title, description, image) for one of them. The first link gets it by default; in the main and reply composers the author can pick another link from the body or no card. Quotes, terminal and API commits always use the first link. Links to YouTube, Vimeo, Loom, Twitch, Spotify, SoundCloud, Apple Music, Suno, CodePen and asciinema get a player in the card that loads only after Play; with no card, there is no player. Media is linked, never uploaded.
- Links: URLs and bare domains in a commit or reply link out. Like X, a long one shows shortened: no `https://` or `www.`, the whole host, then at most 20 characters ending in `…`. Hovering shows the full URL, and copying the text gives it. GitHub repository, issue and pull request links show as `owner/repo` and `owner/repo#123` with the GitHub mark, and links to /dev/null commits as `username/` and a short hash. Links in code stay as written. Link previews (title text and image) shorten them the same way.
- Notifications: in-app only, for a new follower, for a star on one of your commits, for an approved reply to one of your commits (only the direct parent's author; never for replying to yourself), for an approved quote of one of your commits (never for quoting yourself), for an approved commit or reply that mentions you (never for mentioning yourself; the parent's author of a reply or the quoted author of a quote hears about it as a reply or quote, not twice), and for a rejected commit, with the moderator's reason. A notification points to the follow, star, reply, quote, or mention, it never copies it: it disappears when the commit, the commit it replies to or quotes, or either user is deleted, and is hidden while the follow or star is undone, the commit is not approved, or the actor is muted or blocked. A follower notifies once, ever: unfollowing and following again never pings twice. Pending replies, quotes, and mentions notify nobody until approved. Stars group per commit, follows per day, and replies and mentions per thread, each group expandable; filters (Replies, Quotes, Stars, Mentions, Follows, Moderation) are remembered. A new follower can be followed back, or unfollowed, right from the list. Unread count in the nav, polled every 30 seconds; opening Notifications marks everything read.
- Search (⌘/Ctrl+K or `/`, and `/search`): developers by name or GitHub username (up to 8), and commits and replies by meaning, through embeddings and an AI relevance check, 3–100 characters, 15 searches a minute. Results only include what the viewer may see, without muted or blocked people. Guests can search too.
- Mute and block: muting someone silently hides their commits, replies, notifications, and suggestions from you; follows stay, their profile still opens with a "Muted" badge, and Saved keeps their commits. Blocking someone removes follows both ways, stops follows, replies, stars, pastéis, remotes and Tom between you, hides each other's commits while signed in, and makes their profile unavailable to you. Unblocking doesn't restore follows. Both are listed and undone in Settings → Safety. Blocking is not a way to hide public commits from guests.
- Remotes (direct messages): on by default, and can be turned off in Settings; while off, nobody can message you, Remotes is hidden, and your conversations are kept for when you turn it back on. One-to-one messages up to 2,000 characters, at `/remotes`, with up to 3 images (same limits and descriptions as commits), replies to a message, link cards, typing indicators, and emoji reactions (any emoji, up to 12 different ones per person per message; three quick ones and double-tap for ❤️). Messages can't be edited or deleted, and mentions in them notify nobody. You can push to people who follow you, and people you follow can push to you; once a conversation exists, either side can keep pushing. Two parts are built but turned off for now, each re-enabled by config: **requests** (`REMOTES_REQUESTS`), where anyone else's first message lands in **Fetched** until you **merge** it, they can send only that one, and **dropping** it hides it without telling them; and **everyone** (`REMOTES_EVERYONE`), letting people choose to take remotes from anyone. Read receipts (**pulled**) are on by default, optional, and mutual. **Orgs** are group remotes of up to 100 people, with an optional name up to 60 characters: the creator is a **maintainer** and everyone they add is a **contributor**. Maintainers add people who follow them (choosing whether they see past history), remove people, rename the org, and promote or demote; an org always keeps a maintainer, anyone can leave, and if the last maintainer leaves, the longest-standing member inherits. Membership changes show as lines in the history, and pulls show as the avatars of who has read. Site admins can push to, and add to orgs, anyone with remotes on. Nobody can push to someone with remotes off (Tom included), and pickers say why someone can't be messaged or added. Conversations can be **stashed** (they pop back to Open when anyone writes), searched by name or handle, blocked from inside, and the inbox can be docked to the bottom of every page on desktop. Messages arrive by polling, not websockets (every 1.5 seconds in an active conversation, slower when idle, never in a hidden tab): sends are optimistic and show staged → pushed → pulled. Message bodies are encrypted at rest with the app key, not end to end. Exports include the messages you sent; deleting an account deletes your side of its conversations and the messages you sent.
- Export: Settings → Profile → Download JSON gives the account's profile, commits and replies (deleted ones still stored included), polls and own votes, stars, saved commits, follows, mutes, blocks, sent messages, notifications, SSH key fingerprints, devices, and session metadata. Never secrets, session ids, or other people's votes. 3 an hour.
- Rate limits, per user: commits 10/min (shared), stars and saves 60/min each, pastéis 60/min, pins 20/min, follows 30/min, reports 5/min, translations 10/min, people lookups (search, mention suggestions, hover cards) 120/min combined, commit search 15/min, remote messages (and creating or adding to orgs) 30/min, every other Remotes request 300/min, Sync from GitHub 1/min, issues 5/hour, exports 3/hour. Guests are limited per IP for search and lookups. Throttled actions keep the page and show a toast; throttled pages show the 429 page.
- Public read API and Atom feeds: read-only, so nothing can be created, starred, or followed through them, and there are no API tokens. Lists are cursor-paginated, 20 per page.
- Deliberately excluded for now: editing commits, likes or reactions on commits (stars and pastéis are the only engagement; emoji reactions exist only on remote messages), reposts without a comment of your own (quotes are in), uploading video or audio (players come from links), hashtags, other OAuth providers, passwords and API tokens, email and push notifications, header/banner images, cloud drafts. Future work must not design for these as if they exist.
- GitHub username renames: signing in, or Sync from GitHub, takes the current GitHub username. If a stale account still holds it because its owner renamed on GitHub, that account moves to a `_renamed-<github id>` placeholder until its owner signs in or syncs again. Accounts are matched by GitHub id and never merged.

## Brand Commitments

- Name: **/dev/null**, written exactly like the path (lowercase, both slashes). The domain is `dev-null.sh`. `devnull` (no slashes) is only for identifiers where a slash cannot go: the database, file names, env vars, the SSH signature namespaces (`devnull-commit`, `devnull-commit-images`, `devnull-api`).
- Voice: dry, terminal-literate humor. Understated wit; copy may wink at Unix and `/dev/null`, but stays clear and never obscures what an action does.
- Current tagline in use: "A social network for developers."
- Vocabulary: a post is a **commit** and a timeline is a **log**, in the UI and in code (`Commit` model, `LogController`, `/log/{log}`). The git metaphor stops at those two nouns, except inside Remotes, which carries its own small vocabulary: a conversation is a **remote**, sending is a **push**, a read receipt is **pulled**, a request is **fetched** until **merged** or **dropped**, archiving is **stash** and **pop**, a group is an **org** of **maintainers** and **contributors**, and **HEAD** marks where you left off. Unix shows up in flavor, not in labels: achievement names, Unix ranks, `stash@{0}` on restored drafts, `fatal: bad object` when a commit vanishes. No branches, forks, diffs, or PRs. **Star** is the engagement verb, not a git ref.

## Evidence on Hand

- No testimonials, metrics, or press to quote. Do not fabricate user counts, quotes, activity, or endorsements.
- Seeded/factory data exists for development only and is not real evidence.

## Product Principles

1. **GitHub is the source of truth for identity.** Never add profile editing on /dev/null or alternate sign-in.
2. **Keep it stupidly simple.** Commits, follows, stars, logs. Every addition must justify itself against the "not now" list.
3. **Words over mechanics.** The post body is the content; chrome and metadata stay subordinate to it.
4. **Wit in the copy, clarity in the action.** Humor lives in tone, never in labels a user needs to understand.
